# 固定流程实现与本地验证

本文记录 [PR #1](https://github.com/beyondchenlin/BKSOP/pull/1) 的实际实现边界。完整产品需求仍以 [详细 PRD](../prd/001-mobile-workflows/PRD.md) 为准；代码完成、自动测试通过、手机实测通过是不同状态。

## 开发方式

功能分支 `feat/mobile-workflows-20261102` 向 `dev` 提交草稿 PR。PR 建立后，拉取明确的提交到独立本地工作树测试；发现问题继续提交到同一 PR。官方镜像、开发集成分支和发布分支不直接改写。

本轮原生固定流程不依赖 AutoJS 或额外 Linux 运行环境。外部助手负责生成参数，固定执行调用原项目的 `ActionExecutor`，没有创建普通 `AgentLoop`。

## 已加入的代码

| 部分 | 行为与关键入口 |
| --- | --- |
| 流程与版本 | `core/workflow/WorkflowContracts.kt`、`WorkflowCodec.kt`：明确版本、参数、本机绑定、步骤、成功条件和内容摘要；同版本异内容拒绝覆盖 |
| 手机持久化 | `FileWorkflowStore.kt`：独立原子替换文件；写入失败保留原数据并停止继续派发；重启后恢复账本，未决效果不自动重放 |
| 运行服务 | `WorkflowService.kt`：提交前验证、启停、不可变任务快照、请求去重、等待项版本、取消和指定目标版本的受限补做 |
| 模型边界 | `ModelExecutionPolicy` 在计量层及 HTTP 请求边界拦截固定上下文内的模型请求；记录被阻止的尝试 |
| 同机协调 | `DeviceExecutionGate` 协调原生界面动作；固定流程持有连续执行段，等待用户时释放；并发子协程不能偷用父许可 |
| 原生适配 | `assembly/WorkflowActions.kt` 使用现有手机工具；唯一控件匹配，实际动作前再次核对；不组装视觉、模型、脚本或自动收尾 |
| 手机宿主 | `AndroidWorkflows.kt` 管理权限、连接、会话及环境摘要；`WorkflowForegroundService.kt` 提供执行通知和停止入口 |
| 手机界面 | 侧边栏“我的流程”；创建/编辑结构化定义，导入导出，本机绑定、验证、启用、运行和任务证据 |
| 外部工具 | `McpWorkflowTools.kt` 将五个固定流程工具加入已有 MCP 连接；手机上每个流程单独授权，默认关闭 |

目前制作界面使用结构化 JSON 定义和参数表单。原聊天能力保留，但“把一次自然语言制作直接转换为流程”的自动录制与修复入口尚未实现。

## 当前流程格式

首版是明确顺序的步骤，可包含 `ACTION` 与 `WAIT_USER`，尚未提供条件分支图或循环。流程声明最终成功条件，对外业务动作还必须有动作前后条件。

- `{{param.name}}` 引用本次任务的已声明参数。
- `{{binding.name}}` 引用接收方手机的本机绑定；这部分不进入导出包。
- 完整字符串占位符保留 JSON 原类型；嵌入文本只接受标量。
- 条件中的包名、可见文本存在或不存在必须全部满足。不可读、不稳定或受保护页面不能算通过。
- `READ_ONLY` 为读取，`LOCAL` 为本机准备，`EXTERNAL` 为对外业务效果；实际原生风险检查仍执行，不能仅通过改声明绕过授权。
- 共享文件包含定义及摘要，不包含任务记录、本次参数、作者本机绑定或验证结果。作者主动写进定义的常量本身属于共享内容，应在导出前检查。

当前文件大小上限为 1 MiB。格式未知、未知字段、摘要不符和不支持的工具被明确拒绝。摘要用于检测内容变化，不等于作者数字签名。

### 支持的原生工具

`phone_launch_app`、`phone_observe`、`phone_list_elements`、`phone_query`、`phone_tap`、`phone_type_text`、`phone_clear_text`、`phone_scroll`、`phone_swipe`、`phone_press_key`、`phone_back`。

点击和输入使用 `selector`，例如：

```json
{
  "selector": {
    "text": "标题",
    "resourceId": "com.example.app:id/title"
  },
  "text": "{{param.title}}"
}
```

条件为同时匹配。没有匹配或存在多个匹配时失败；不从别人的手机保存坐标、元素编号或快照编号。滑动只支持当前唯一目标的纵向操作；输入与提交分为不同步骤。首版不支持组合脚本、任意 shell、付款确认或任意坐标动作。

### 本机验证含义

只读或本机准备流程必须达到声明的成功条件。存在对外动作时，未授权真实效果的验证停在该边界；只有最后一步对外动作可以在提交前验证后启用，并明确保留“真实业务效果未验证”。对外动作之后还有未走过的步骤时，不能凭前半段验证启用整个流程。

正式执行需要流程已启用、定义及本机适配与验证一致、当前环境一致；对外效果还需要本次请求明确授权。执行完成由条件和账本判断，不能仅凭“点击函数返回”宣称业务成功。

## 外部调用契约

复用现有经过认证的手机所有者连接；这不是新的多用户云授权服务。连接凭据不进入流程文件。手机侧还必须对该具体流程打开远程调用开关。

| 工具 | 必要输入与作用 |
| --- | --- |
| `bksop_workflow_list` | 可选 `device_id`；列出当前手机上启用、验证环境匹配且明确授权的流程及参数结构 |
| `bksop_workflow_run` | `device_id`、`installation_id`、`workflow_version`、`request_id`、`parameters`；明确提交一次任务 |
| `bksop_workflow_status` | `device_id` 及 `run_id` / `request_id` 之一；只读查回手机持久账本 |
| `bksop_workflow_resume` | `device_id`、`run_id`、当前 `wait_id`、`state_version`、布尔 `answer`；只回答当前等待项 |
| `bksop_workflow_cancel` | `device_id`、`run_id`；停止后续操作，不撤销已发出的效果 |

正常启动可带明确 `adaptation_version`；真实业务需要 `allow_external_effects: true`。调用方身份由连接宿主注入，客户端不能提交 `caller_id`。界面动作、自然语言目标和模板版本不能通过启动参数覆盖。

外部工具应保留同一业务请求的 `request_id`。启动响应丢失时按它查回，不能制造新编号重发。手机返回查询未找到与连接超时是不同结果；离线时不能拿网关状态替代手机账本。

状态输出只投影任务状态、步骤状态、等待原因、模型调用计数及本机证据引用，不序列化定义、绑定、完整参数快照、图片或原始界面树。远程授权撤销会阻止后续调用，并停止该流程已受理的远程任务。

原有普通任务工具仍保留。需要固定执行的外部 Skill 应只调用这五个流程工具，不能转用普通自然语言任务工具，否则进入的是原有模型任务路径。

## 恢复规则

相同调用方和请求编号对应同一个任务；改变参数或版本后复用原编号会得到冲突。等待回答只接受当前等待项及状态版本，重复回答不能推动下一步。

动作派发前先记检查点。进程中断、提交结果不明或取消时未能完整保存结果，保留“待核实”，不自动重做。成功、仍在执行和待核实步骤不能被新版补做覆盖。

补做使用新请求并带 `source_run_id`、明确且已验证的目标流程版本及本机适配版本、完整 `remaining_step_ids`。首版仅允许已失败/已停止且无未知检查点的任务，在保持原参数、绑定及已完成前缀一致时补做安全后缀；同时竞争由原子关联资格限制。目标可以是原版本或已修复的新版，原任务自身不换版。

## 本地测试

验证必须针对 PR 的实际提交。命令沿用上游：

```powershell
.\gradlew.bat :core:test :core:cliTest :app:testDebugUnitTest -PmikaPython=python
.\gradlew.bat :app:assembleDebug
```

需要 JDK 17、Android SDK（compileSdk 36）及 Python 3.10 以上。具体机器配置以本轮构建记录为准。测试覆盖模型边界、全局界面许可、版本和分享、环境变化、任务账本、MCP 参数与权限、原生工具适配及手机表单输入。测试实现使用假的屏幕端口和本机 HTTP 测试服务，不调用付费模型或真实发布平台。

本文件初次加入时，测试已经编写，Gradle 编译与执行尚未完成；后续实际结果在 PR 描述中更新，不将静态检查写成测试通过。
