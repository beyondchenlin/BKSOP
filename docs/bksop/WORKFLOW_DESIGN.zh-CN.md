# 安卓通用流程分享与外部调用方案

产品：BKSOP（安卓自动化产品）  
日期：2026年11月2日  
状态：目标方案与接口契约；不是已完成功能清单。二开仓库已经建立，业务能力尚待实现。

## 产品定位

本产品是在 MIKA（开源手机智能体）基础上继续二开的通用手机自动化产品。新增的核心能力是：流程制作与分享、接收方本机适配和验证、按明确参数固定执行、供外部助手调用。视频多平台发布只是首个验证案例，不把产品缩减为视频发布工具。

保留原项目已有的普通智能体、手机操作、文件处理等能力。制作调试与固定运行共用同一套手机执行器。当前完整产品方案不引入 AutoJS（安卓自动化脚本工具）作为执行依赖，也不要求用户额外安装终端环境或独立桥接应用。

## 完整使用链路

流程作者在自己的手机上制作并调通一项业务流程，将其导出成带版本和参数规范的流程包。接收用户导入后，在自己的手机上验证并保存本地适配。满足本机条件并启用后，外部助手就能发现并调用这条流程。

日常使用时，外部助手只理解用户文字、生成文案和结构化参数，通过已经接通的工具接口启动手机上的已启用流程。手机普通程序解析本机资源，执行固定操作，返回状态和结果。结果可以继续由外部助手解释给用户。

普通运行不重新调试，不把相同需求再交给内部模型理解。未覆盖异常返回具体原因；需要智能修复时，进入独立的制作修复模式，并记录相应模型用量。

## 四类核心对象

| 对象 | 必备内容 | 边界 |
| --- | --- | --- |
| 共享流程包 | 格式版本、流程标识、不可变版本、内容摘要、名称、说明、输入输出规范、动作和分支、等待条件、成功判据、恢复规则、所需能力及适用条件 | 不携带作者的账号凭据、私有素材、个人路径或临时会话信息 |
| 本机安装记录 | 所安装流程版本、启用状态、本机账号和资源绑定、授权范围 | 每台手机独立保存，不替换其他用户的设置 |
| 本机适配与验证记录 | 流程摘要、设备和应用环境、定位规则、验证范围、时间与结果 | 验证对应明确环境；超出兼容条件时要求重新验证 |
| 运行记录 | 请求编号、流程版本、本次参数、已解析资源、当前状态、动作检查点、子任务结果、错误与完成证据、内部模型调用计数 | 一次运行锁定版本与适配；不在运行中自动升级流程 |

共享流程包不得通过导入任意代码获得额外权限。新增流程只引用当前执行器已经注册并允许的能力；能力缺失时明确拒绝启用。

## 流程状态与本机验证

流程安装状态包括：待适配、验证中、可启用、已启用、已停用、需要重新验证。导入只创建安装记录，不自动执行。

验证结果必须区分：

- 本机适配通过：已检查所需资源、页面定位及各动作前置条件，实际验证范围写入报告。
- 实际效果已验证：相应业务动作真实执行后已取得结果证据。

试运行在每一个会产生外部效果的动作之前执行边界检查，不能只在流程最后一个提交动作前停止。普通读取、可恢复的本机准备动作以及已经明确授权的测试动作可以执行；其余动作仅验证前置条件，并在报告中标记实际效果尚未验证。真实执行过的业务动作直接计入任务记录，正式运行不得再次重做。

在视频示例中，提交前测试不能被描述为已经证明真实发布成功。首次真实发布计入正式任务记录，不再重复发布一次所谓正式版本。需要真实测试的动作必须在明确的测试任务范围内执行。

账号登录、系统授权等需要用户本人完成的条件，按实际状态提示；不把授权缺失当成页面定位失败。

## 参数、资源与动作的通用设计

### 参数

流程自行声明输入参数和约束。核心层只实现类型、必填、长度、范围和引用有效性检查。

“标题”“标签”“抖音账号”“待发布相册”属于视频发布示例流程的参数或绑定，不成为所有工作流必填的核心字段。

### 本机资源

本机资源解析的通用契约为：接收明确查询条件，使用普通代码解析，固定本次资源清单，将访问引用交给后续动作。

外部助手可以原样传递用户提供的文件名称或位置，也可以把“最新五个”转换成相册、排序和数量条件。资源解析不调用模型。输入足够明确时，查询和执行在同一次任务内部完成，不要求先把完整素材清单发送给外部模型再做一轮决策。

同一次任务只解析一次相对条件。后续子任务及恢复使用已经固定的资源引用，不能反复查询“最新几个”。重名、缺失、不可读或内容改变，返回明确结果，不由模型猜测替代项。

### 动作

动作通过现有手机执行器统一执行，包括打开应用、查找控件、点击、输入、等待条件、检查状态和解析本机资源。共享包的动作能力必须明确声明并通过安装校验。

每个动作还必须声明其副作用、测试执行规则、成功判据和重试条件；界面点击是否产生业务效果，由该流程的具体动作定义确定，不能仅按“点击”这一动作名称判断。

视频示例增加“选择本次指定素材”动作，显式绑定素材参数。仅保存“点击第一格”不能代表已经验证素材身份。

## 运行模式

| 模式 | 模型使用 | 执行层 |
| --- | --- | --- |
| 普通智能体 | 保留原项目现有模型能力 | 同一套手机执行器 |
| 制作、适配与修复 | 允许使用已配置模型，独立记录用量 | 同一套手机执行器 |
| 固定运行 | 内部模型调用次数必须为零 | 同一套手机执行器 |

固定运行不得进入自然语言任务循环，不调用模型选流程、抽参数、查素材、总结结果、判定成功或执行后台学习评估。运行上下文应在真实模型请求发出前拒绝不允许的模型调用，而不是仅在提示词中要求不用模型。

程序能处理的重试和失败路径仍保持内部模型调用为零。智能修复是独立任务，不能静默接管固定执行并额外消耗模型费用。

## 对外工具接口

一个通用 MCP（模型上下文协议）工具集提供真实执行能力；一个通用 Skill（技能）说明什么时候调用、如何填参、如何读取状态和结果。二者职责不同，可以组合交付。

以下名称为拟定接口，尚未实现，不表示现有产品已提供这些工具。

| 拟定工具 | 输入与行为 | 返回 |
| --- | --- | --- |
| bksop_workflow_list（列出可用工作流） | 在当前用户授权手机范围内发现已启用且验证条件满足的流程 | 流程标识、版本、说明、参数规范、验证范围 |
| bksop_workflow_run（启动固定工作流） | 接收流程版本、标准参数、请求编号；校验并创建运行，不能接受任意改写动作 | 运行编号与实际接收状态 |
| bksop_workflow_status（查询工作流状态） | 查询指定运行 | 状态、进度、输出、错误、等待要求、子任务结果、完成证据与模型调用计数 |
| bksop_workflow_resume（继续工作流） | 携带当前等待项标识或状态版本，提交该等待项允许的信息或明确继续指令，重新校验继续条件 | 更新后的状态；不允许借继续跳过失败校验 |
| bksop_workflow_cancel（停止工作流） | 停止后续动作，保留已完成记录 | 已停止或停止中的实际状态；不声称撤销已产生的外部结果 |

制作、导入、导出、适配、验证和启用属于手机内的流程管理。外部助手默认只运行已准备好的流程，不默认获得修改手机执行步骤的能力。

通用连接技能应随已启用流程清单动态发现能力，不为每个用户、每条流程重新制作一份连接技能。不能从通用技能退回调用原来的自然语言任务入口。

## 任务状态与防重复

运行状态包括：已创建、准备中、执行中、等待用户、已暂停、结果待核实、停止中、已成功、已失败、已停止。

运行查询、继续和停止均须校验当前调用者对该手机及该运行的访问权限。请求去重范围绑定调用者身份与目标设备；相同请求编号比较流程标识、流程版本和全部规范化输入，不跨用户或设备共享去重结果。继续请求只能对应当前等待项；过期或重复继续请求不得推动新的等待步骤。

- 在同一去重范围内，相同请求编号和相同流程、版本、参数返回已有运行，不创建第二份任务。
- 相同请求编号但流程、版本或参数不同，返回冲突。
- 手机离线、服务已收到请求、手机已经接收任务、实际执行成功，必须分别显示。
- 长任务先返回运行编号，再通过状态查询取回结果，不把连接超时当作任务未执行。
- 提交动作发生后结果丢失，进入结果待核实，先查结果，禁止直接重做提交。
- 只有明确声明可安全重试的动作才允许有限重试。
- 每个业务子任务独立保存结果，成功部分不因其他子任务失败而重做。
- 同一手机的前台界面操作统一受控排队，即使目标应用不同也不能并发争用屏幕；与界面无关且不修改共享状态的查询可以并行。

接受停止请求后进入“停止中”；只有执行器确认不再开展后续动作，才进入“已停止”。已经发起且结果尚不明确的外部动作，其子任务继续保留“结果待核实”，不能因父任务停止就将其记为未执行。

## 外部助手与手机的连接

用户端只安装本产品，设备绑定、授权、通信和结果回传能力内置。外部工具运行在云端时，仍需要能够到达手机的通信通道。

复用原项目已有的手机主动连接远程网关基础，并在产品化时补齐多用户、多设备归属和授权隔离。通道只传任务参数、必要状态及用户允许的结果，不为本案例上传视频进行模型分析。

“无需另装桥接应用”不等于“无需通信服务”。如果禁止所有服务端转发，不能同时承诺指定云端助手可以在任意网络环境下自动调用普通手机。

豆包工作及 WorkBuddy（腾讯办公助手）的具体手机运行模式，必须实际完成工具接入、授权、任务调用和结果返回联调后才能列为已支持。公开文档中产品总体支持技能或连接器，不等同于每一种手机运行模式已验证可用。

外部免费额度按照对应产品账号规则使用；连接能力不把消费端额度转换成可供本产品任意调用的模型接口。

## 视频发布示例的专属规则

该示例使用现成视频，用户文字交代内容与发布要求。全链路不分析视频语义，不把视频、视频帧或缩略图作为模型分析输入。

用户可提前准备固定待发布相册、唯一名称和明确顺序。本机程序查询文件信息并固定清单。目标客户端在导入和发布时读取素材并上传。系统自身的媒体索引与缩略图等本机行为不属于模型视频分析。

素材选择方式在接收方调试时确定：已验证的本机文件导入或分享入口、可核验的完整文件名选择，或者有明确相册范围和已验证排序条件的固定选择。不能仅凭本机查到名称、再点第一格就宣称完成了名称与位置的双重核验。

某个平台只有缩略图而无法建立可靠对应关系时，必须收窄待选范围或明确提示无法定位；不能让模型猜测视频内容。

每个视频与每个平台、账号的发布结果单独记录。标题、标签、平台名称及其限制全部保留在该示例流程与平台适配中，不渗入通用核心。

后续其他自动化场景复用同样的分享、验证、参数、资源、动作、任务和外部连接能力，不需要新增一套工作流底座。

## 成品验收要求

- 原项目已有普通智能体能力仍可用，产品没有退化为单一发布工具。
- 同一流程包能在不同接收方手机中独立适配，互不修改对方绑定。
- 未验证、停用或兼容条件不满足的流程不能被外部正式调用。
- 固定运行的正常路径和程序处理的失败路径，内部模型调用计数均为零。
- 用户指定资源得到准确绑定，资源选择歧义和权限不足被明确报告。
- 导入、校验和试运行不会隐式产生未经测试范围授权的业务效果；视频示例的提交前试运行不会产生正式发布。
- 首次真实任务直接计入正式结果，重试不会重复提交。
- 外部助手只能调用其授权手机上已启用的能力。
- 外部接口实际支持长任务状态、继续、停止、断线及结果待核实。
- 视频示例没有把视频内容发送给模型进行分析。
- 不要求额外安装自动化脚本运行器或用户自行维护桥接程序。
